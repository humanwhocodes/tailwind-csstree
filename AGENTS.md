# Agent Guide

## Project overview

Tailwind CSSTree is a JavaScript/TypeScript-checked library that extends `@eslint/css-tree` to parse Tailwind CSS v3 and v4 syntax. The package exports `tailwind3` and `tailwind4` from `src/index.js`; consumers use them with CSSTree's `fork()` function.

## Repository layout

- `src/tailwind3.js` and `src/tailwind4.js` define the version-specific syntax extensions.
- `src/atrule/`, `src/node/`, `src/scope/`, and `src/types/` contain reusable at-rule, syntax-node, function-scope, and value-type definitions.
- `tests/tailwind3.test.js` and `tests/tailwind4.test.js` cover each syntax; shared test helpers are in `tests/helpers/`, and CSS fixtures are in `tests/fixtures/`.
- `dist/` is generated by the TypeScript compiler from `src/` and is the package output.
- `eslint.config.js` configures JavaScript and CSS linting, including this package's Tailwind syntax for its fixtures.
- `.github/workflows/` contains Node.js and Bun CI workflows.

## Development

- Requires Node.js 18.18 or newer.
- Install dependencies with `npm ci`.
- Build and type-check with `npm run build`.
- Run unit tests with `npm run test:unit`; run the full suite, including package type checks, with `npm test`.
- Lint with `npm run lint`; format with `npm run fmt`.
- `npm run test:jsr` checks JSR publishing and requires access to the Deno registry, so it may fail in network-restricted environments.
- CI runs lint/build/tests across Node.js and operating-system versions and also runs unit tests with Bun.

## Making changes

- Keep syntax behavior specific to the appropriate Tailwind version and extend existing CSSTree syntax definitions where possible.
- Add or update tests in the corresponding version test file; use fixtures in `tests/fixtures/` when appropriate.
- Preserve existing behavior and avoid changing tests to accommodate unintended behavior changes.
- Run `npm run lint`, `npm run build`, and `npm test` when changing code. Format changed files with `npm run fmt`.
- Do not commit generated build output unless the task specifically requires it.
- Commit messages and pull request titles must use Conventional Commits format (for example, `fix: parse Tailwind variant` or `docs: add agent guidance`).
